第一章 一切的开始
一.app 目录核心内容
​	libs：存放第三方 jar 包，放在此目录下的 jar 包会被自动添加到构建路径。


​	androidTest：用于编写 Android Test 测试用例，实现项目自动化测试。


​	res：存放项目所有资源，包括图片、布局、字符串等。


​	drawable：存放图片资源


​	layout：存放布局文件


​	values：存放字符串、样式、颜色等配置


​	mipmap：存放应用图标


​	AndroidManifest.xml：项目全局配置文件，所有四大组件都需要在此注册，也可声明应用权限。


​	test：用于编写 Unit Test 测试用例，是自动化测试的另一种方式。


​	build.gradle（app 模块）：app 模块的构建脚本，指定项目构建相关配置。


​	proguard-rules.pro：指定项目代码的混淆规则，防止代码被破解。


二.资源引用规则
​	代码中引用


​	格式：R.类型.资源名


​	示例：R.string.hello_world


​	XML 中引用


​	格式：@类型/资源名


​	示例：@string/hello_world


​	资源类型替换


​	图片资源：替换为 drawable


​	应用图标：替换为 mipmap


​	布局文件：替换为 layout


​	AndroidManifest.xml中的源代码

​	Log.v()：级别：verbose	作用：打印琐碎、意义最小的日志

​	Log.i()：级别：info	作用：打印重要业务数据，分析用户行为


​	Log.w()：级别：warn	作用：打印警告信息，提示潜在风险


​	Log.e()：级别：error	作用：打印错误信息，如异常捕获场景

七.活动的生命周期
活动的4 种状态：
运行状态


活动位于返回栈栈顶，与用户交互，系统最不愿回收，避免影响用户体验


暂停状态


活动不再处于栈顶，但仍然可见（如对话框式活动覆盖），活动完全存活，仅在内存极低时可能被系统回收


停止状态


活动不再处于栈顶，且完全不可见。


系统会保存状态和成员变量，但内存不足时可能被回收


销毁状态


活动从返回栈中移除，系统最倾向于回收，保证手机内存充足


活动的生存期：
七种回调方法：


onCreate():活动第一次被创建时被调用，完成活动初始化（加载布局、绑定事件）


onStart():活动由不可见变为可见时被调用


onResume():活动准备好与用户交互时被调用，活动一定位于栈顶，处于运行状态


onPause():系统准备启动 / 恢复另一个活动时被调用，释放 CPU 资源、保存关键数据（执行速度需快）


onStop():活动完全不可见时被调用


onDestroy():活动被销毁前被调用，活动变为销毁状态


onRestart():活动由停止状态变为运行状态前被调用，活动重新启动时触发


完整生存期：onCreate() ↔ onDestroy()，完成初始化与内存释放


可见生存期：onStart() ↔ onStop()，活动对用户可见，可管理可见资源


前台生存期：onResume() ↔ onPause()，活动处于运行状态，可与用户交互


八.活动的启动模式
一共四种启动模式
Standard（标准模式）
默认启动模式，无显式指定时默认使用


每次启动必创建新实例：每次启动该模式的 Activity，系统都会创建新实例并加入返回栈


栈内可存在多个实例：同一 Activity 可在返回栈中创建多个实例，按启动顺序入栈


退出逻辑：需按返回栈顺序，逐个按 Back 键销毁实例，直至栈空才退出程序


每次启动→新建实例→入栈多实例共存，返回键逐次出栈


SingleTop（栈顶复用模式）
栈顶复用，非栈顶新建：启动 Activity 时，若该 Activity已在返回栈栈顶，则直接复用栈顶实例，不创建新实例；若不在栈顶，则创建新实例并入栈


生命周期回调：复用栈顶实例时，会回调onNewIntent()（而非onCreate()）


无重复栈顶实例：栈顶位置永远只有一个该 Activity 的实例，避免栈顶重复创建


栈顶有→复用；栈顶无→新建；核心解决「栈顶重复创建」问题


增加android:launchMode=”singleTop”即可（下面的一样）






SingleTask（栈内复用模式）
栈内唯一，全局检查：整个应用的返回栈中，该 Activity 只会存在一个实例；启动时系统会遍历整个返回栈，检查是否已有该 Activity 实例


实例复用 + 清空上层：若栈内存在该 Activity 实例，系统会直接复用该实例，并将该实例之上的所有 Activity 全部出栈销毁，使该 Activity 成为新栈顶


生命周期回调：复用实例时回调onNewIntent()，上层 Activity 销毁时会执行onDestroy()


栈内有→复用 + 清空上层；栈内无→新建；核心解决「栈内重复创建多个实例」问题，实现 Activity 全局唯一






SingleInstance（单实例模式）
最特殊、最复杂：四大模式中唯一独占独立返回栈的模式


独立返回栈：该 Activity 会启用一个全新的、独立的返回栈，与其他 Activity 的返回栈完全隔离


全局唯一实例：整个系统中，该 Activity 只会存在一个实例，且所有应用共享这个独立栈中的实例


返回逻辑特殊：启动该 Activity 时进入独立栈，按 Back 键时，先退出独立栈，再回到之前的应用栈
