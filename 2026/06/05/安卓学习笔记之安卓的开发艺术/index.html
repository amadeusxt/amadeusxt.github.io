安卓的开发艺术

一.关于Activity

典型的Activity 生命周期

生命周期流程

如果从后台重新回到前台：

生命周期方法说明

onCreate()

Activity 创建时调用

常用于：

  • 加载布局（setContentView）
  • 初始化控件
  • 初始化数据

onStart()

Activity 对用户可见时调用

特点：

  • 页面已经显示
  • 但还不能与用户交互

onResume()

Activity 进入前台并获得焦点

特点：

  • 用户可以进行操作
  • Activity 处于运行状态

常用于：

  • 开启动画
  • 开启定位
  • 注册监听器

onPause()

Activity 即将失去焦点时调用

特点：

  • 仍然部分可见
  • 用户即将离开当前页面

常用于：

  • 保存临时数据
  • 暂停动画
  • 暂停视频播放

onStop()

Activity 完全不可见时调用

常用于：

  • 释放不需要的资源
  • 停止后台任务

onRestart()

Activity 从停止状态重新启动时调用

执行顺序：

onDestroy()

Activity 销毁时调用

常用于：

  • 释放资源
  • 取消网络请求
  • 解除监听器

生命周期总结

方法 状态 常见用途
onCreate 创建 初始化页面
onStart 可见 页面显示
onResume 前台运行 用户交互
onPause 失去焦点 保存数据
onStop 不可见 释放资源
onRestart 重新启动 从后台恢复
onDestroy 销毁 清理资源

记忆口诀

创建 → 可见 → 运行 → 暂停 → 停止 → 销毁

在 Android 中，如果启动的是一个透明主题（Translucent）Activity，下面的 Activity 仍然有可能保持可见，因此通常不会进入 onStop()，但会进入 onPause()

Activity的第一次启动：onCreate->onStart->onResume

当用户再次回到原Activity时，回调：onRestart->onStart->onRtesume

当用户按下back键回退时，回调：onPause->onStop->onDestroy

Activity 启动时的生命周期切换

新 Activity 启动流程

当启动一个新的 Activity 时：

  1. 当前 Activity 先回调 onPause()
  2. 新 Activity 开始创建并进入前台
  3. 原 Activity 随后回调 onStop()（如果完全不可见）

对于新 Activity 的启动，旧 Activity 的 onPause() 必须先执行完成，新 Activity 才会继续启动

⚠️ onPause() 和 onStop() 都运行在主线程中，应避免耗时操作

⚠️ 不要在 onPause() 中执行重量级任务，否则会导致新 Activity 启动变慢，影响用户体验，如有需要，可以在onStop中做

资源相关配置变化导致 Activity 重建
什么是资源相关配置变化

当系统配置发生变化时，Android 默认会销毁当前 Activity 并重新创建，以便加载新的资源

常见情况：

  • 屏幕旋转（横竖屏切换）
  • 系统语言切换
  • 字体大小改变
  • 深色模式切换
  • 屏幕尺寸发生变化（折叠屏展开等）
Activity 重建流程

配置发生变化后，Activity 会经历如下生命周期：

系统会先销毁旧 Activity，再创建新的 Activity 实例

onSaveInstanceState()

在 Activity 被系统销毁之前调用

作用：

  • 保存临时状态数据
  • 保存界面状态
  • 为 Activity 重建提供数据恢复依据

示例：

onRestoreInstanceState()

在 Activity 重建后调用

作用：

  • 恢复 onSaveInstanceState() 保存的数据
  • 恢复用户离开前的界面状态

示例：

数据恢复的两种方式
方式一：onCreate()
方式二：onRestoreInstanceState()

区别：

  • onCreate() 不一定有保存的数据
  • onRestoreInstanceState() 被调用时，savedInstanceState 一定不为 null
注意事项
  1. onSaveInstanceState() 只适合保存少量临时数据
  2. 不要保存大对象或大量数据
  3. 数据库、文件等持久化数据不需要放入 Bundle
  4. View 的状态（如 EditText 输入内容）系统通常会自动恢复
  5. Activity 因用户主动退出（如按返回键 finish()）时，通常不会调用 onSaveInstanceState()

资源不足导致 Activity 被系统回收

什么是资源不足回收

当系统内存不足时，为了保证前台应用正常运行，Android 会主动回收处于后台的 Activity 所占用的资源

当用户再次返回该 Activity 时，系统会重新创建 Activity，并尝试恢复之前保存的状态

Activity 被回收的场景

常见情况：

  • 应用切换到后台后长时间未使用
  • 系统可用内存不足
  • 同时运行大量应用
  • 大型游戏或高内存应用占用资源

  • 输入框内容
